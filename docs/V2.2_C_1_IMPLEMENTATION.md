## 本轮补完

1. **真正移除 100 条上限**：删除 `saveAttempt` 的 100 条抛错和 `parseStudy` 的 `history.length > 100` 拒绝；`decodeBackup` 不再按 100 切块，而是一次校验完整数组。历史容量改由 IndexedDB 配额与 64 MB 备份上限约束，不再有记录条数上限，也不自动裁剪。
2. **兼容快照改为真实最近记录**：新增 `recent(limit)`，分别取最近 quiz 与 review，按时间倒序合并；镜像写入最近 20 条（时间升序）并保留 `historyStorage` 标记。
3. **分页正确性**：每页多取 1 条判断 `hasMore`，恰好 20 条时不再显示可点的空页；横轴标签按页偏移显示真实第 N 次。
4. **导出确定性与一致性**：导出按 `at`、`id` 排序；Provider 导出改读已提交的 head，避免把未保存的乐观 profile 与已提交历史拼在一起。
5. **失败回滚**：写入失败时把 UI 恢复到 IndexedDB 已提交的 profile，并保留明确警告；测验提交失败不显示分数。
6. **测试补强**：101 条、1001 条、旧档案超过 100 条、镜像最近 20 条、导出时间有序、分页与统计；并给异步落盘后的既有 reload 断言加轮询等待，不删除或放宽原断言。

## 存储与迁移

- 权威数据：IndexedDB。`head.profile` 不含 `study`，历史单独存行；`analytics` 增量聚合，导入时重算。
- 兼容层：`cyberpath.v1` 仍保留，内容是完整 profile 加最近 20 条历史及 `historyStorage` 标记，只用于旧页面/旧版本读取，不是权威源。
- 首次迁移：读取旧 `cyberpath.v1` → `parseProgress` → 单个 readwrite 事务写入全部历史行、`legacy-source` 原文备份、新 head → 校验行数 → 提交 → 写兼容快照。任一步失败事务回滚，旧 key 不动。
- 中断恢复：事务未提交则不产生 head，下次打开重新迁移；重复打开已有 head 不会重新迁移。测试覆盖“中途 abort 后刷新重试”。
- 丢失保护：若 IndexedDB 被清空但 localStorage 还有带 `historyStorage` 的兼容快照，应用拒绝把它当完整档案，提示导入完整备份，不会静默丢历史。
- 导入：先 `decodeBackup` 全量校验 profile、版本、每条历史、ID 唯一，再在单事务中安装；失败不改变当前 head。导入/重置都会建立新 generation，旧 head 与原文留在 `backups` 供回滚，界面和导出只读当前代。
- 导出：`version:2`，包含完整历史、题目快照、笔记、收藏、词汇复习、课程进度；不含第二份 `study`。

## 边界与风险

- IndexedDB 不可用：只读降级，明确提示且禁止假装保存；`recordAttempt` 返回 false，测验不显示分数。
- 配额不足：事务回滚，head 与分数不变，提示导出并检查存储。
- 多标签页：revision 与兼容快照双重检测；检测到冲突暂停保存，要求导出并刷新，不做自动合并。
- localStorage 被禁用：当前实现回退为只读；IndexedDB 单独可用但 localStorage 不可用的组合尚未支持写入。
- 浏览器清理站点数据仍会删除 IndexedDB；用户需自行导出。多设备不同步。
- 重置保留旧 generation 作为本地回滚备份，不是彻底擦除；需要彻底清除时应清理站点数据。
- 旧版本程序可能忽略 `historyStorage`，并只看到最近 20 条；跨版本同时写入不在兼容承诺内。
- 大备份导入受 64 MB 限制；极端数据量下的导入耗时未做压力测试。
