# CyberPath V2.2 开发路线

日期：2026-11-09。依据：[实际源码审计](V2.1_AUDIT.md)。基线是当前 HEAD `7b41db3` / package 2.1.1，而不是从 V1 重做。本文件是计划，不表示任务已经实施；本次没有业务代码变更。

## 1. 版本目标与不做事项

V2.2 的目标是让前三课形成可靠的“阅读 → 解释术语 → 实验 → 作答 → 复习 → 保存/恢复”闭环。先解决可确认的数据与流程缺陷，再完善零基础教学，不扩大为综合云平台。

保留现有 Next.js App Router、React、TypeScript、Tailwind、Context、本地内容与 localStorage。保留三课主题顺序、15 道现有题目、34 词词库、四个实验框架、双主题与简约双语设计。不要重复实现登录、词汇页、评分引擎、导入导出或子网算法；账号目前不存在，V2.2 也不把新增账号当“修复”。

本期不引入 AI API、收费服务、云数据库、真实攻击靶场、任意命令执行、完整 CMS、强制状态管理库或大型 PWA 依赖。后五课保持明确预告；新课程发布另立内容验收任务，不为凑数生成正文。

## 2. 优先级与发布门槛

- P1：F01 导入类型漏洞、F02 原始数据保护、F03 队列不可继续；以及受支持环境可重复生产构建与浏览器验收。
- P2：真实成绩时序、书签与题目稳定 ID、迁移、教学支架、实验练习、移动可访问性。
- P3：有实测依据的性能改善、样式整理、可选记忆计划。
- 当前未确认 P0，不把未实现云功能当严重故障。

所有业务任务必须先定义失败复现或回归用例，再修改实现。每个独立变更通过相关检查后 commit/push，不能把环境失败或未执行测试标记为通过。不更改系统安全设置，不关闭沙箱；构建若仍受环境限制，在正常可写的受支持执行环境/CI 验证，保留失败记录。

## 4. 依赖关系和任务组织

主线：T01/T02（数据安全）→ T05/T06（语义与迁移）→ T07/T08（档案可靠性）→ T09–T13（内容与双语）→ T14–T16（实验任务）→ T17–T20（收口）。T03 与 T04 可独立先做；T16 算法测试可独立进行，但不擅自扩展功能。本文件的并列任务表示依赖关系，不授权本次启动开发或多代理。

阶段大小 S/M/L 仅表示相对工作量；本轮浏览器受环境阻塞，尚不能给可靠日历排期。开始阶段 1 后，依据干净构建耗时、失败复现与真机反馈再估算。每阶段以可验收增量交付，不一次性合入全部修改。

## 5. 数据与安全约束

- 导入失败、未知版本、配额满、权限被拒绝都要保护当前档案；恢复原文不等于把原文作为可执行 HTML 渲染。
- schema 是否升到 2 由实际事件/ID模型决定。若新增语义改变，应明确迁移器与备份，而不是仅修改界面版本号。旧数据缺时间时允许 null/unknown。
- 内容 ID、题库版本和词汇 alias 应有明确唯一性检查；labId 应用联合类型，预告与完整课程应在类型上区分。
- 云同步前先定义存储适配接口、revision 与冲突策略；本期不引入云账号/数据库。
- 不执行用户输入系统命令，不搭建外部扫描接口，不写入 API Key，不修改防火墙，不以关闭沙箱“修复”构建。

## 6. V2.2 最终验收与回滚

1. F01/F02/F03 都有可失败的回归用例，并在修复后通过；没有静默数据丢失或卡住的复习队列。
2. 最近成绩与访问时间解耦；合法 V1/V2 备份可迁移，失败导入保留现有数据；题目/章节改名不破坏旧档案。
3. 三课关键知识人工复核、实践输出可判读、术语辅助在手机可用；不把课程预告当完整教材。
4. 原有单元与浏览器基线加本期新用例全部通过，CI 结果可追溯；构建失败不能发布。
5. 桌面和手机实测结果分开记录，真机/PWA/HTTPS 未执行时明确标记；不把 WebKit 模拟当 iPhone。
6. 每阶段有独立 commit；schema 迁移前自动保留备份；代码回滚与数据回滚步骤分别写清。没有必要为本次审计创建 V2.2 标签。

在阶段 1 达标前，优先稳定现有平台；在阶段 5 达标前，不应把“新功能数量”当作版本成功标准。
