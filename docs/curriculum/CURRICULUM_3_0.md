## 0. 一句话定位

CyberPath 3.0 的目标是 **From Zero to Engineer**：让中文母语学习者从完全零基础开始，用英文教材系统学习计算机科学、软件工程、网络安全与工程实践，并通过可验证的项目证据逐步接近技术岗位的真实要求。

课程完成 **不等于** 达到职业标准。本体系用「知识 → 练习 → 项目 → 证据」四层结构，把课程学习与能力验证分开记录、分开判定。

## 1. 范围与边界

本文件定义长期知识体系，不定义发布计划。以下内容明确不在本轮范围：

- 不新增或修改 `src/content/lessons/index.ts` 的课程数据。
- 不修改 `cyberpath.v1` 存储结构、schema 版本或导入校验。
- 不实现新页面、新实验、新测验组件。
- 不部署、不打标签、不合并 `master`。
- 不承诺学完即可就业，不承诺任何企业会录用。

现有 Lesson 1–3 继续作为兼容基线；Lesson 4–8 的既有预告保留为候选内容，但不再视为平台终点。

## 2. 设计原则

1. **零基础可进入**：Level 0 不假设学习者会安装软件、会用命令行、能读英文技术句。
2. **知识有依赖，编号无依赖**：课程编号只用于排序与展示，先修关系由独立的知识依赖图定义（见 `KNOWLEDGE_DEPENDENCIES.md`）。
3. **每个模块有可观察的学习成果**：目标使用可验证动词（解释、计算、配置、复现、修复、评审），不使用「了解」「熟悉」作为唯一标准。
4. **实践优先于叙述**：每个模块至少一个实验或练习；每个阶段至少一个综合项目。
5. **安全与伦理是前置条件**：所有攻击性内容只在授权靶场、模拟环境或学习者自有系统中进行。
6. **英文为主、中文为辅**：正文英文，术语给中文释义；专业英语本身作为可评估能力。
7. **证据驱动评级**：等级由作品、实验记录、答辩与迁移测试决定，不由学习时长或答题数量决定。
8. **可持续扩展**：新增课程沿固定模板接入，不复制页面、不重建存储模型。

## 3. 结构模型

```
Domain（领域）
└── Track（学习路径）
    └── Module（模块，可独立验收）
        └── Lesson（课程，一次 25–45 分钟学习单元）
            └── Learning Objective（可观察目标）
```

### 3.1 稳定 ID 规则

| 层级 | 格式 | 示例 | 说明 |
| --- | --- | --- | --- |
| Domain | `D01`…`D13` | `D05` | 永久不变 |
| Track | `T-<DOMAIN>-NN` | `T-NET-02` | 领域内两位序号 |
| Module | `MOD-<DOMAIN>-NN` | `MOD-NET-03` | 模块序号，不复用 |
| Lesson | `L-<DOMAIN>-MMNN` | `L-NET-0301` | MM 模块号，NN 课序号 |
| Lab | `LAB-<DOMAIN>-NN` | `LAB-NET-02` | 实验/模拟器 |
| Project | `P-NN` | `P-18` | 项目，跨领域 |
| Capability | `CAP-<ROUTE>-NN` | `CAP-SEC-03` | 岗位能力项 |

规则：

- ID 一旦发布不得改写；课程改名、拆课、合并都保留旧 ID 作为别名。
- 删除课程不删除 ID，标记 `retired` 并保留迁移映射。
- 课程编号（`number`）只影响展示顺序，不参与依赖判定。
- 现有应用内课程 ID（`network-foundations`、`dns-tcp-web`、`ip-subnets-nat` 等）作为 `contentId` 保留，与 `L-*` 建立多对一映射（见迁移计划）。

### 3.2 课程单元模板

每节新课程固定包含（现有 Lesson 1–3 在迁移阶段逐步补齐，不强制回填）：

1. **Objectives**（2–4 条，可观察）
2. **Why it matters**（1 段，连接真实场景）
3. **Concept sections**（3–6 节，英文正文，稳定 section ID）
4. **Vocabulary**（2–4 个术语，中文释义 + 英文定义）
5. **Command / output reading**（涉及系统操作时提供脱敏示例，网站不执行命令）
6. **Lab or exercise**（至少一个可操作任务）
7. **Quiz**（5 题，含解释；题目 ID 稳定）
8. **Review hook**（与已有知识建立复习连接）

### 4.1 为什么是 13 个领域（合并与拆分的理由）

- **Operating Systems（D04）与 Linux and System Administration（D09）保持拆分**：前者是原理课，评估方式是机制解释与模拟实验；后者是操作能力课，评估方式是在 Windows/Linux 环境完成配置、排障与文档。合并会导致「懂原理但不会操作」或反之，两者都必须单独验收。
- **Cloud、DevOps 与 Infrastructure 合并为 D10**：招聘市场通常把三者视为同一技能簇（云平台 + 容器 + 交付流水线 + 可观测性），学习路径高度重叠。内部拆为 4 条 Track，避免把「会用某个云厂商控制台」当成工程能力。
- **Computer Systems and Architecture（D11）独立**：体系结构解释性能、内存安全与二进制行为，是安全与系统岗位的共同基础，不能塞进操作系统。
- **Advanced Computer Science（D12）独立且不进入必修**：分布式、编译、密码学进阶、机器学习属于深化内容，独立后可以明确「核心路径不要求全部完成」。
- **Engineering Projects and Career Readiness（D13）作为能力域而非知识域**：它不教新理论，负责把知识转化为可验证的工程证据与职业表达，因此必须有独立模块和独立评分标准。
- **Cybersecurity（D08）拆为 6 条 Track**：安全岗位分工差异大（防御运营、应用安全、渗透测试、身份、治理），单一路径会制造「什么都学一点」的假能力。共同基础收敛到 `T-SEC-01`，其余按岗位分化。
- **Web（D06）与 Backend（D07）拆分**：两者的失败模式、调试工具与安全风险不同；合并会弱化数据库与 API 契约训练。
- **Programming（D02）不按语言分领域**：Python 与 TypeScript 是两条 Track，共享同一套工程习惯模块，避免「学了两门语法但不会调试」。

## 5. 五个学习阶段（摘要）

详细准入与验收见 `KNOWLEDGE_DEPENDENCIES.md` 第 3 节。

| 阶段 | 名称 | 学习者应掌握 | 应能完成 | 验证方式 |
| --- | --- | --- | --- | --- |
| L0 | 完全零基础 | 计算机组成直觉、文件与账号、浏览器与网络常识、技术英语入门 | 独立管理文件与账号；解释一次网页访问；读懂入门英文教材 | 任务清单实操 + 口试 + L0 测验 |
| L1 | 计算机与编程基础 | 一门语言基础、命令行、Git、网络基础三课、Linux 入门、Web 基础 | 写 100–300 行程序；完成抓包/子网/终端练习；提交规范 commit | 3 个基础项目 + 实验记录 + 代码评审 |
| L2 | 核心计算机科学 | 数据结构、算法、操作系统、网络协议、数据库、Web 交互 | 实现并解释常用数据结构；写 SQL；分析一次真实抓包；定位性能问题 | 课程测验 + 基准实验 + 诊断任务 + 项目 |
| L3 | 专业方向学习 | 安全、云、后端、网络或系统方向的核心技能 | 独立完成方向实验与报告；按基线加固系统；复现并修复一类漏洞 | 方向项目 + rubric + 同行评审 |
| L4 | 综合工程实践 | 多组件系统设计、交付、可观测性与事故处理 | 端到端交付一个可运行系统并写清取舍；处理一次故障演练 | Capstone + 运行证据 + 答辩 |
| L5 | 职业能力深化与高级专题 | 高级专题、研究能力、技术表达与迁移能力 | 在陌生问题上做取舍；复现公开漏洞或论文；指导他人 | 高级项目 + 公开复现 + 答辩 + 迁移测试 |

等级不是时间刻度：允许学习者跳过已掌握内容，但**不允许跳过证据**。任何等级提升都必须提交对应证据包。

## 7. 教学法规范（所有新课程必须满足）

### 7.1 课程结构

每节课 25–45 分钟，英文正文 500–1200 词，按 L0→L5 递增。固定节奏：

1. **Hook**：一个真实问题或错误现象。
2. **Model**：概念与心智模型，配一张图或一个类比。
3. **Worked example**：完整演示一次，包含失败与修正。
4. **Guided practice**：有提示的分步任务。
5. **Independent practice**：无提示任务，进入实验或项目。
6. **Check**：5 题测验 + 1 个「解释给别人听」的口头任务。

### 7.2 学习成果写法

- 使用可观察动词：`explain`、`calculate`、`configure`、`diagnose`、`reproduce`、`fix`、`review`、`design`。
- 禁止把「understand」「know」「be familiar with」作为唯一目标。
- 每条目标必须能对应一种证据：测验题、实验输出、项目产物、口头答辩或迁移任务。

### 7.3 实验与项目边界

- 实验（Lab）：15–40 分钟，聚焦一个机制，可重复、可自动判定。
- 项目（Project）：数天到数周，跨模块，必须包含设计、实现、验证与文档。
- 所有攻击性实验只在本地模拟器、隔离虚拟机或书面授权靶场内进行；平台不提供真实目标扫描能力。

### 7.4 复习与反馈

- 每个模块结束时生成「错误概念清单」，进入间隔复习队列。
- 词汇复习与知识复习分开：词汇考「能否在句中理解」，知识考「能否在新情境应用」。
- 项目评审使用统一 rubric（见 `PROJECT_BASED_LEARNING.md`），至少包含技术正确性、安全性、测试、文档与表达五项。

## 9. 评估与证据体系

### 9.1 四类证据

| 证据 | 形式 | 判定 |
| --- | --- | --- |
| E1 知识 | 测验、口试、错题复习 | 正确率 + 错误概念是否消除 |
| E2 实验 | 实验记录、截图、输出、日志 | 可复现、结论有依据 |
| E3 项目 | 仓库、部署、测试、文档 | rubric 达标 + 红线项为零 |
| E4 迁移 | 新情境任务、答辩、同行评审 | 能解释并调整方案 |

### 9.2 红线项（任一不通过即项目不通过）

- 在未授权系统上进行测试或攻击。
- 提交含真实密钥、个人信息或他人数据。
- 伪造实验输出、测试结果或项目证据。
- 项目无法被他人按文档复现。

### 9.3 等级判定

等级判定使用「最低证据门槛」，不是平均分：

- L1：完成 3 个基础项目 + 3 个基础实验 + 通过 L1 综合测验。
- L2：完成 2 个核心项目 + 1 次诊断任务 + 通过 L2 综合测验。
- L3：完成 1 个方向项目 + 1 份专业报告 + 同行评审通过。
- L4：完成 2 个 Capstone + 1 次事故演练 + 答辩通过。
- L5：完成 1 个高级专题项目 + 1 次公开复现或论文复现 + 答辩通过。
