## 1. 依赖模型

### 1.1 三种关系

| 类型 | 标记 | 含义 | 违反后果 |
| --- | --- | --- | --- |
| 硬先修 | 直接列出模块 ID | 缺少该知识会导致当前模块无法完成 | 学习受阻，实验无法通过 |
| 软先修 | 写在括号中，标「建议同时修」 | 有助于理解，但不阻塞 | 可跳过，需额外查证 |
| 并行 | 无依赖声明 | 可在同一阶段任意顺序学习 | 无 |

硬先修是**知识依赖**，不是「课程编号更小」。例如 `MOD-SEC-01` 编号在 `MOD-LNX-01` 之后，但安全基础只依赖网络与数字素养，不依赖 Linux。

### 1.2 为什么编号不能作为依赖依据

1. 编号按领域聚合，跨领域学习顺序是自由的（可以先学网络再学编程，也可以反过来）。
2. 同一领域内可以并行（`MOD-NET-05` 与 `MOD-NET-06` 都只依赖 `MOD-NET-02`）。
3. 后续插入课程时若依赖编号，只能追加到末尾，破坏教学顺序。
4. 编号会因展示需要调整（合并领域、重排 Track），依赖不能随之失效。

因此：**依赖只存在于模块表与本节规则中**，展示编号 `number` 只是渲染顺序。

### 1.3 阶段单调规则

- 设 `stage(module)` 为难度标注的起始等级（L0=0 … L5=5）。
- 对每条硬边 `A → B`（B 依赖 A），要求 `stage(A) ≤ stage(B)`。
- 同阶段内允许依赖，但被依赖模块必须在推荐学习序列中更早出现（见第 4 节典型路径）。
- 若需要「低阶段模块依赖高阶段模块」，说明难度标注错误，必须调整标注而不是放宽规则。

## 3. 五级阶段定义

等级由**证据**判定，不由学习时长、课程数量或答题数量判定。允许跳级申请，但必须一次性提交该等级的出口证据包。

### L0 — 完全零基础

| 项目 | 内容 |
| --- | --- |
| 入口 | 会开关机、能使用浏览器；无需编程或英语基础 |
| 核心能力 | 文件与路径、账号与隐私、浏览器与网络常识、计算机组成直觉、技术英语入门 |
| 必修模块 | `MOD-CF-01`、`MOD-CF-02`、`MOD-CF-03`、`MOD-CF-04`、`MOD-CF-05` |

### 3.1 等级晋升流程

1. 学习者提交证据包（项目链接、实验记录、报告、演示视频/现场答辩）。
2. 评审按 rubric 打分，红线项任一触发即不通过（见 `PROJECT_BASED_LEARNING.md` 第 6 节）。
3. 未通过时给出「缺什么证据」而不是「再学一遍」。
4. 等级记录与课程完成记录分离：完成课程不等于升级，升级也不要求学完所有课程。

## 6. 环检测与一致性审计

### 6.1 方法

1. 从 `CURRICULUM_3_0.md` 的 86 个模块块解析 `先修：` 字段。
2. 提取 `MOD-*` 标识；括号内标记为软边，不参与拓扑判定。
3. 用 DFS 三色标记检测环；用 Kahn 算法求拓扑序。
4. 计算最长依赖链；检查每条硬边的阶段单调性。
5. 校验课程 ID 唯一性、每模块课程数、实验与项目字段完整性。

### 6.3 未纳入自动检查的项

- 软先修是否合理（需要教学判断）。
- 课程内容是否真的覆盖目标（需要内容评审）。
- 英文难度是否与等级匹配（需要语言评审）。
- 项目 rubric 是否可执行（需要试评）。

这些项在迁移计划中列为人工门禁。

## 7. 依赖维护规则

### 7.1 新增模块

1. 至少声明 1 条硬先修，除非属于 L0 入口。
2. 硬先修不超过 3 条；超过需在模块说明中解释为何不能拆分。
3. 新模块的阶段不得低于任一硬先修阶段。
4. 同步更新：模块块、本文件表格、总数统计、关键路径（如影响）。
5. 运行第 6.1 节的检查，确认 0 环。

### 7.2 拆分模块

- 保留原 ID 给其中一个子模块，另一个使用新 ID。
- 原模块的依赖边重新分配到子模块，禁止两条边同时指向「已拆分」的旧 ID。
- 已发布课程的 ID 不改；用别名映射到新模块。

### 7.3 合并模块

- 保留被合并方 ID 作为 `retired`，在新模块中记录 `supersedes`。
- 依赖边取并集，去重后重新审计。
- 旧档案中的课程记录仍按原 ID 读取，不迁移、不删除。

### 7.4 退役模块

- 标记 `retired`，保留 12 个月只读访问。
- 不再计入必修，但保留在依赖图中直到所有下游模块完成替换。

## 8. 待决问题

1. **数学基础**：`MOD-ADV-05` 密码学进阶与 `MOD-ADV-06` 机器学习是否需要独立数学模块（线性代数、概率）？当前以「够用即可」的方式嵌入，后续视学习者反馈决定。
2. **Windows 与 Linux 比例**：现有平台以 Windows 命令为主，而岗位更常用 Linux。计划在 L1 引入 Linux 实验（浏览器内终端模拟 + 本地虚拟机指南），不强制安装双系统。
3. **实验环境成本**：抓包、容器、Kubernetes 实验需要本地环境或远程沙箱，涉及成本与安全边界，需在 V2.4 前定方案。
4. **等级认证的公信力**：自学平台的等级证据如何避免自评偏差？计划引入同行评审与抽样人工复核，具体比例待定。
